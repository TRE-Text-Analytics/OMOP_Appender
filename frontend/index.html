Step 03

Patient scope
Existing + create new patients
Import clinical data for existing target patients and add brand-new person records for source-only patients. Default behaviour.
Existing patients only
Only import clinical rows for patients already in the target (matched by person_source_value). Source-only patients and the person table are skipped entirely.
Sample mode
Limit to first N patients (for fast iteration)

Deterministic by person_id ascending. Filter pushes into SQL so a 100-patient sample of a 169M-row clinical table only streams the matching rows.

Person record — if patient already exists in target
Skip (keep existing)
Preserve the target person record as-is. Only import new clinical events for that patient.
Upsert (update demographics)
Overwrite gender, race, year_of_birth etc. with source values where they differ.
Abort on conflict
Halt the entire import if any existing patient is encountered. For strictly audited pipelines.
Clinical event deduplication
Skip rows already present in target

Dedup key per table: person_id + event concept_id + event start date. Compares source rows against rows that existed in target before the run; legitimate repeats within source (e.g. ICU vitals sampled hourly) flow through as distinct rows.

Primary key remapping

A source→target ID mapping CSV is exported after every run.
